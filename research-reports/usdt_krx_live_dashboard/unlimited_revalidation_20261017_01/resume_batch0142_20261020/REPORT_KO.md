## 재개 시 수정한 실행 연결

전략 엔진·지표·비용 산식·원본 입력은 수정하지 않았다. 기존 D: 이전 코드의 research_storage 모듈을 프로세스 안에서 연결했고, 기존 사용자 설치 Python 3.12.0 / NumPy 2.2.6 / Numba 0.61.2 / pandas 3.0.1을 사용했다. 새 패키지 설치나 전역 환경 변경은 하지 않았다.

run_one_batch.py는 기존 runner의 배치 루프만 7050~7099번째 등록 조건으로 제한하고, 게시 대기 위치에서 반환하도록 한다. 기존 claim_study 잠금을 사용해 중복 워커를 차단했다. 기존 stale lock은 원래 로직대로 별도 이름으로 보존됐다. 감사 완료된 생성 엔진은 다시 생성하지 않고 읽어 실행했으며, 실행 전후 엔진 및 사전등록 해시 일치를 확인했다.

계산 전 첫 시도는 JSON에 저장된 entry_range_abs_pp의 문자열 키와 메모리 정수 키 비교 때문에 사전등록 대조에서 중단됐다. 아직 batch_0142가 생성되기 전이었다. 래퍼에서만 비교값을 JSON 왕복 정규화했고 등록 설정 자체는 수정하지 않았다. 이후 정확한 기존 condition_grid의 다음 50조건과 결과 설정을 대조해 전부 일치했다.

원장 감사는 저장된 trades/events/residuals에서 사이클 분모·순손익·수수료·슬리피지·완료 횟수·잔여 수량을 독립적으로 재집계했다. 50조건 모두 결과 CSV와 일치했다. 가격 입력은 승인된 EXPLORATORY 사본만 사용했으며, 보호된 Final OOS 파일은 열지 않았다.
