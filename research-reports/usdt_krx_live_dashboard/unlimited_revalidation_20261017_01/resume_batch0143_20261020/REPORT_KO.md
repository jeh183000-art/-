## 계산·비용 기준

각 완료 사이클 수익률은 해당 사이클의 비용 차감 순손익을 그 사이클에 실제 진입한 모든 세트의 현물 진입금액 절대값 합계로 나눈 백분율이다. 후보의 점수는 이 값을 반올림하지 않고 단순 합산한다. 초기 투자금, 선물계좌 자금, 총순이익을 점수의 분모나 순위에 넣지 않았다.

기존 편도·레그별 2bp 슬리피지와 600_PLUS_CLEARING_ASSUMED 수수료 정책, 롤오버, 다음 연속 분봉 시가 대용 체결, 불연속 구간 처리와 무제한 자금 로직을 그대로 사용했다. 펀딩은 KRX 만기 선물이므로 0 / 해당 없음이다. 원시 호가 체결이 검증된 실거래 수익률이 아닌 승인된 탐색용 PAPER 결과다. 역배는 USDT 차입 가능성과 차입 비용이 검증되지 않은 이론값이다.

## 실행과 보존 검증

1. batch_0142의 PUBLISHED_VERIFIED 체크포인트와 원격 23파일을 다시 대조했다. batch_0143이 로컬·원격에 없고 동일 워커가 없음을 확인했다.
2. 기존 단일 배치 래퍼에서 대상 범위만 condition_grid.csv의 7100~7149번째 50조건으로 옮겼다. 기존 claim_study 잠금 방식을 그대로 사용했다.
3. 첫 시도는 내부 모듈 이름을 배치 번호와 함께 바꾼 탓에 기존 Numba 캐시가 frozen_unlimited_batch142를 찾지 못해 중단됐다. 첫 전략의 계산 전 오류였으며, 실패 시도의 trades/events/residuals는 모두 헤더 외 0행이었다. 해당 폴더를 incomplete_attempts/batch_0143_cache_alias_20261020에 보존했다.
4. 전략이나 패키지를 바꾸지 않고 캐시의 기존 모듈 이름을 유지하도록 래퍼만 수정했다. 이후 50조건 계산이 완료됐다. 기존 batch_0142나 다른 완료 배치를 재계산하지 않았다.
5. 생성 엔진, 실행·수익률·위험 모듈과 사전등록 파일의 실행 전후 SHA-256이 일치했다. 실제 결과의 50개 조건 ID·방향·진입·추매·회복폭·슬리피지가 고정된 다음 50조건과 정확히 일치했다.
6. 저장한 체결·이벤트·잔여 원장에서 사이클 분모, 순손익, 수수료, 슬리피지, 잔여 수량, 완료 수 및 수익률 합계를 독립적으로 재집계해 50/50 PASS를 확인했다. 무제한 자금·증거금·계약 수 제한에 의한 진입 거절은 0건이다.
7. 실행 후 worker.lock.json이 없고 동일 Python 워커도 없었다. batch_0144는 없다.

Python 3.12.0, NumPy 2.2.6, Numba 0.61.2, pandas 3.0.1의 기존 설치를 사용했다. 프로세스의 연구 경로·캐시·임시 파일은 기존 D: 저장 설정을 따랐고 전역 환경이나 실행환경 패키지는 수정하지 않았다. 승인된 EXPLORATORY 입력 사본만 읽었으며 보호된 Final OOS 파일은 열지 않았다.
